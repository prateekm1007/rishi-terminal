against the locale catalog and reports missing / empty / orphan keys,
with the core-flow subset (nav, common, header, language, dashboard,
screener, stock, portfolio, rishis, chat, legal, pricing —
`lib/i18n/coreNamespaces.ts`) called out explicitly. It now runs in CI
(`ci.yml`, quality job, after score parity).

## 2. The Playwright acceptance — fail-first then pass

`test/e2e/i18n.spec.ts` (new; `playwright.config.ts` testDir widened to
`./test` with `testMatch: **/*.spec.ts` so the Vitest `*.test.ts` suites
stay out of Playwright's collector). The pseudo-locale
(`messages/pseudo.json`, every string bracketed and expanded ~40% —
`node scripts/genPseudoLocale.mjs` regenerates) is reachable only via
localStorage: it is NOT offered in the LanguageSelector UI.

Fail-first (spec against a build without the pseudo-locale provider
support — `pseudo` was not in the provider's persisted-locale list, so
English rendered and the expanded-string poll timed out):

```text
  2 failed
    test/e2e/i18n.spec.ts:30:7 › … switching language persists across reloads
    test/e2e/i18n.spec.ts:51:7 › … pseudo-locale (expanded strings) shows no overflow on the top 10 pages
```

(The persistence test's first failure was a locator bug in the spec
itself — the trigger has no aria-haspopup; fixed to
`button:has-text("English")`. The assertion also initially targeted the
sidebar logo "RISHI TERMINAL", which is brand text, not a catalog key —
switched to "डैशबोर्ड". Both spec fixes are honest test-of-the-test
iterations, recorded here.)

Post-fix, on the branch build:

```text
$ npx playwright test test/e2e/i18n.spec.ts --reporter=line
  2 passed (18.5s)
```

- Persistence: selector → हिंदी → nav renders डैशबोर्ड/स्क्रीनर → reload
  → still Hindi; `localStorage.rishi_locale === 'hi'`.
- Overflow: all 10 pages (/, /screener, /stock/{SBIN,RELIANCE,TCS,INFY},
  /rishis, /chat, /news, /methodology) render the expanded pseudo strings
  with `documentElement.scrollWidth <= clientWidth + 1`.
