# Security master sources — provenance

**Every row in `securities` / `symbol_history` / `universe` traces back to a file in
this directory. A row without a source is a bug (Constitution art. 6).**

---

### Refresh

Re-fetch the URL (from a network allowed to reach it), name the file
`nse_equity_l_<YYYY-MM-DD>.csv`, record the SHA-256 here, then regenerate
`populate.sql`:

```bash
npx tsx scripts/populateSecurityMaster.ts            # reads the newest CSV in data/security-master/
git diff data/security-master/populate.sql           # review what changed
```

The generator always reads the **newest** `nse_equity_l_*.csv` and stamps the
filename into every emitted row's `source` column, so any consumer can trace a
row back to the exact snapshot it came from.

## `populate.sql` (generated — do not hand-edit)

Generated by `scripts/populateSecurityMasterImpl.ts` from the newest CSV above
plus `lib/registry/tickerAliases.json` and the seed dataset
(`data/stocks/index.ts`, 944 placeholder records — symbols and names only; the
numeric placeholders are never read here). Applied by the CI "migrations" job
and to the live database. Idempotent (upserts + `ON CONFLICT DO NOTHING`).

Resolution rules, in order (the generator never guesses an ISIN —
Constitution/roadmap D1-02):

1. **Direct symbol match** — a seed symbol appears verbatim in the official
   listing → that row's ISIN.
2. **Name resolution** (for seed symbols not in the listing) — normalize the
   seed company name and every official name (lowercase, strip punctuation and
   corporate suffixes: *ltd, limited, plc, india, co, corp, corporation,
   company*). If the seed's name tokens are **fully contained** in exactly ONE
   official row's tokens → that row's ISIN, with the match recorded in the
   emitted `universe.reason`. If two or more official rows contain the seed
   name → **UNRESOLVED**, both candidates recorded in the reason. Zero
   candidates → **UNRESOLVED** ("delisted, renamed with a name change, or not
   a real listing").
3. Everything else → `universe` row with `isin IS NULL`, `data_quality =
   'UNRESOLVED'` and the reason.

`symbol_history` rows emitted:

| Kind | `valid_from` | `valid_to` | `source` |
|---|---|---|---|
| Official listing row | official `DATE OF LISTING` (caveat above) | `NULL` (current) | `nse:equity_l:<snapshot-date>` |
| Seed-era symbol variant (seed symbol ≠ live symbol, name-resolved) | `NULL` (unknown) | `NULL` (no claim) | `seed:placeholder:<snapshot-date>` |
| Registry alias (old user-input symbol → canonical seed symbol, from `tickerAliases.json`) | `NULL` (unknown) | `NULL` (no claim) | `tickerAliases:T12:2026-09-30` |

Rows with `source='seed:…'` / `'tickerAliases:…'` make **no exchange-validity
claim** — the NULL dates mean "unbounded" for resolution, and the `source`
column is what tells the truth about where the mapping came from. Real
symbol-change dates arrive with licensed corporate-actions data (D1-03) and
will supersede these rows.

`universe` rows: one per official listing symbol
(`data_quality='PENDING_DATA'` — prices/fundamentals ingestion and validation
are D1-04..D1-09, which is what promotes rows to `OK`), plus one per
UNRESOLVED seed symbol (`isin IS NULL`, symbol + reason recorded).
